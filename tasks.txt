# Core Development Principles

Follow these rules throughout the entire modernization.

## 1. Prefer minimal code

Always prefer the simplest implementation that solves the problem correctly.

Do not introduce:

* unnecessary abstractions
* unnecessary classes
* unnecessary helper functions
* unnecessary dependencies
* unnecessary background workers
* unnecessary microservices
* unnecessary state management
* unnecessary framework migrations
* unnecessary design patterns

Prefer:

```text
small functions
clear modules
explicit dependencies
simple data flow
few moving parts
```

Use the principle:

> The best code is the smallest amount of code that clearly and reliably solves the problem.

---

# 2. Delete unused code

Actively search for and remove:

* dead code
* unused functions
* unused imports
* commented-out implementations
* duplicate functions
* duplicate imports
* obsolete TODO code
* experimental code no longer used
* empty files that have no purpose
* abandoned modules
* unused templates
* unused CSS
* unused JavaScript
* unused assets
* unused backend folders
* stale configuration
* deprecated dependencies

Do not retain code merely because it might theoretically be useful later.

Git history already preserves deleted code.

Before deleting something, verify that it is not referenced elsewhere.

---

# 3. Remove commented-out implementations

Examples such as:

```python
# calendar_service = ...
# appointment = ...
# db.session.add(...)
```

should not remain indefinitely.

Choose one implementation.

Either:

```text
implement it
```

or:

```text
delete it
```

Do not leave large blocks of commented-out application logic.

---

# 4. Avoid premature microservices

Keep Voice2Appointment primarily as a:

```text
MODULAR MONOLITH
```

Separate processes are acceptable only when runtime requirements justify them.

Examples:

```text
Flask web application
Async voice gateway
Celery worker
Optional NVIDIA STT worker
```

Do NOT introduce:

* Kubernetes
* Kafka
* RabbitMQ
* service mesh
* complex orchestration

unless there is a concrete requirement.

---

# 5. Preserve working functionality

After every phase:

1. run tests
2. run linting
3. verify application imports
4. verify database migrations
5. verify critical workflows
6. fix regressions before starting the next phase

Do not stack broken changes across phases.

---

# 6. Make small commits / logical changes

Each task should represent one understandable change.

Avoid giant rewrites.

Prefer:

```text
fix bug
test bug
commit
```

before moving to another problem.

---

# 7. Remove dependencies when standard library can do the job

Examples:

Prefer:

```python
zoneinfo
```

over:

```python
pytz
```

when possible.

Prefer simple Python structures over adding large frameworks.

Every new dependency must have a clear reason.

# PHASE 7 — Real-Time Voice Performance

---

# Task 7.1 — Remove the 400 ms audio buffer

Inspect:

```python
BUFFER_SIZE = 20 * 160
```

The Twilio stream is μ-law 8 kHz.

This creates approximately:

```text
400 ms
```

of avoidable buffering.

Forward Twilio media chunks to the speech provider with minimal buffering.

Benchmark before and after.

---

# Task 7.2 — Add queue backpressure

Use bounded queues.

Example:

```python
asyncio.Queue(maxsize=50)
```

Do not allow memory usage to grow indefinitely if a speech provider becomes slow.

# Task 17.5 — Audio conversion layer

Twilio provides:

```text

8 kHz
```

Create a tiny normalization layer only for providers requiring it:

```text

        ↓
PCM
        ↓

        ↓
NVIDIA STT
```

Avoid converting Deepgram audio unnecessarily.

# Task 17.6 — NVIDIA runtime isolation

Do NOT load a large NVIDIA model inside every Flask worker.

Preferred architecture:

```text

  ↓

  ↓
```

The NVIDIA model may run in:

```text

```

if memory/concurrency permits.

Otherwise:

```text
separate GPU worker/service
```

is acceptable.

Only separate it when resource constraints justify it.

# What Not To Do

Do NOT:

* migrate everything to FastAPI merely because it is newer
* migrate frontend to React solely to use MUI
* create microservices unnecessarily
* introduce Kafka
* introduce Kubernetes
* introduce RabbitMQ without need
* duplicate appointment logic for Deepgram and NVIDIA
* store user configuration in source files
* store large analytics datasets in browser sessions
* load an NVIDIA model per request
* cache sensitive audio unnecessarily
* blindly cache every endpoint
* silently swallow exceptions
* use broad bare `except:`
* leave unused commented code
* leave old implementations beside new implementations
* create abstractions before they have two real use cases
